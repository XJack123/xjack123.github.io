# Jack · 个人网站 v2

黑白灰为主色，荧光黄绿点缀。多页面结构，原生 HTML / CSS / JavaScript，兼容 GitHub Pages，不需要安装依赖。

## 页面

- `index.html`：只有自我介绍段落与模块入口按钮。
- `about.html`：个人 CV：教育背景、项目经历、技能、实践及可选联系方式。
- `projects.html`：项目列表与标签筛选。
- `project.html?id=…`：独立项目详情、外部链接、项目文件下载。
- `gallery.html`：照片瀑布流、分类筛选、点击大图。
- `notes.html`：学习与思考列表，支持分类筛选与全文搜索。
- `note.html?id=…`：笔记独立阅读页，支持标题、列表、引用与代码块。
- `admin.html`：个人资料编辑、照片管理、项目及附件管理、草稿、预览、备份与 GitHub 发布。

网站不虚构学校、项目和户外经历。首页与个人 CV 根据本地简历整理；项目列表与照片仍留待从管理台正式添加。

## 第一次上线：完整网站

1. 登录 GitHub 账号 `XJack123`。
2. 创建公开仓库 `xjack123.github.io`。如果已有同名仓库，请先保留原有内容的备份。
3. 将完整网站 ZIP 解压，把里面的所有网页、样式、脚本和图标上传到仓库根目录。`index.html` 和 `admin.html` 应直接位于根目录。不要只上传 ZIP，也不要把外层文件夹一起上传。
4. 仓库 **Settings → Pages → Source** 选择 **Deploy from a branch**，再选择上传文件所在的分支（通常是 **main**）和 **/(root)**，保存。
5. 等待 Pages 发布，访问 `https://xjack123.github.io/`。
6. 管理台地址是 `https://xjack123.github.io/admin.html`。也能从网页底部的“内容管理”进入。

本次文件仅在本机生成，尚未替你上传或开通 GitHub Pages。

## 日常更新：管理台

1. 在“个人资料”中填写介绍、头像等，点击保存。
2. 在“研究与项目”中添加或编辑项目；可以上传封面和多个附件。
3. 在“照片管理”中选择或拖入照片，设置分类、日期、地点，然后保存。保存后可以逐张编辑标题和描述、调整顺序。
4. 点击“预览网站”，查看已保存的本机草稿。预览链接带 `?preview=1`，访客不会看到你的草稿。预览页已打开时，再次编辑后需要刷新。
5. 到“发布网站”选择令牌发布，或者下载内容更新包手动上传。

草稿通过 IndexedDB 保存在当前浏览器和当前网站地址下。更换浏览器、设备、域名，或从本地文件切换到线上时，草稿不会自动迁移；请先下载草稿备份，再在新位置导入。清理浏览器数据会清除草稿。

### 方式 A：从管理台发布到 GitHub

- 必须先部署完整网站，并在仓库中启用 Pages。
- 到 GitHub **Settings → Developer settings → Personal access tokens → Fine-grained tokens** 创建令牌。
- Resource owner 选择 `XJack123`；Repository access 只选 `xjack123.github.io`；Repository permissions 中 **Contents** 选 **Read and write**。Metadata 的只读权限会自动包含。设置合适的到期日。
- 在管理台“发布网站”输入令牌，勾选公开发布确认，点击发布。
- 令牌仅在这次操作的内存中使用，只发送到 `https://api.github.com`。不会写入草稿、备份、网页文件或浏览器存储；成功或失败后会清空输入框。不要将令牌发到聊天或提交进仓库。
- 管理台验证 GitHub 账号必须是 `XJack123`。创建一个包含内容与新增附件的提交，并使用非强制更新，避免覆盖并发提交。
- 检测到线上内容版本变化会停止，保留本机草稿。先备份草稿，刷新并核对线上版本后再决定如何合并。
- 管理台显示“已提交”表示 GitHub 已接收提交，不代表 Pages 已完成部署。请等待几分钟，并在仓库 Actions / Pages 中查看部署状态。
- 此实现以仓库默认分支为发布分支，请在 Pages 中选择同一个分支的根目录。分支保护也可能阻止令牌直接发布，需要在 GitHub 按仓库规则操作。

### 方式 B：不使用令牌

- 点击“下载内容更新包”，解压后上传其中的 `site-data.js` 与 `assets/` 文件夹到仓库根目录。
- **保留已有 HTML、CSS、JS 和其他资产文件**。这是增量内容包，不能替代完整网站包。
- 上传完成、Pages 部署后，请重新打开管理台以读取新的内容版本。

## GitHub Pages 下的管理权限

GitHub Pages 是静态托管。`admin.html` 本身可以公开访问，无法通过前端页面提供服务器级私人登录。管理台的本机编辑不会影响网站；实际发布必须通过 GitHub 账号和仓库权限校验。无需令牌的更新包也需要你登录 GitHub 后手动上传。

本方案适合公开的个人主页和单人管理。照片与项目附件发布后是公开文件，不适合存储私人资料。管理台移除一项会从公开页面移除引用；已上传文件及 Git 历史仍保留在仓库中，不进行永久删除。需要真正私有的后台、多人权限或私有文件时，应另接带身份验证和存储的服务。

## 照片与附件限制

- 图片支持 JPG、PNG、WebP、GIF，单张最大 10 MB，每批最多 20 张。
- 上传图片会缩至最长边 2200 像素并转为静态 JPEG，去掉位置等元数据。GIF 会变成静态图，原图需自行保存。
- 项目附件支持 PDF、ZIP、TXT、MD、IPYNB、PY、CSV、PPTX、DOCX、XLSX，每个最大 20 MB，每次最多 10 个。
- 待上传文件总量限制为 60 MB，请分批发布。
- 附件使用随机文件名，页面保留原始文件名供下载。所有用户文字按纯文本显示，不执行上传内容或将介绍作为 HTML 渲染。

## 本地使用

双击 `index.html` 或 `admin.html` 可以使用。也可以在此文件夹运行 `python3 -m http.server 8000` 后打开 `http://localhost:8000/`。不要将带令牌的管理页面放到不信任的网站。

网页内容由 `site-data.js` 提供。草稿预览只对明确带 `?preview=1` 的页面生效，普通页面只读取已发布数据。

## 中英文切换

公开页面右上角提供“中文 / EN”按钮。默认中文，选择会保存在当前浏览器；页面链接也会携带语言参数，因此存储不可用时仍可跨页保留选择。可以用 `index.html?lang=en` 直接打开英文首页。

首页介绍、个人 CV、导航、按钮与内置提示提供人工编写的英文版本，不调用在线翻译服务。在管理台“个人资料 → 英文内容 / English version”中可分别编辑中英文自我介绍、学校、研究方向与城市。英文留空的字段会回退到中文原文；自行上传的项目与照片文字保留输入时的语言。

## 学习与思考

首页和导航中的“学习与思考”进入文章列表。到管理台“学习与思考”里新建文章，填写标题、日期、分类、标签、摘要和正文，也可以补充英文版本。正文支持纯文字、`# 标题`、`- 列表`、`> 引用`以及用三个反引号包围的代码块；不执行 HTML。

保存为“仅草稿”的文章只留在当前浏览器及主动下载的草稿备份中；不会包含在公开的 `site-data.js`、内容更新包或 GitHub 发布内容中。预览可以看到私密草稿，普通页面只展示已公开的文章。选择“下次发布时公开”后仍需到“发布网站”发布，才会同步到线上。

已公开文章改回草稿或移除后，需要再次发布才会从线上页面移除。Git 历史仍可能保留曾经公开的内容，因此私密信息请一直保持草稿状态。

旧版草稿和备份兼容，没有文章数据时按空列表处理。本次新增网页和管理功能属于网站文件更新：如果你已部署旧版，请先上传新版完整网站文件（保留自己的 site-data.js 与 assets 内容），然后再通过管理台更新文章。已有内容请先备份。
